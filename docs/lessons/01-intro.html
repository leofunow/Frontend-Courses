Как устроен веб

Клиент, сервер, фронтенд, бэкенд и архитектуры

90 минут теории, 1,5–2 часа заданийСлайды к урокуСценарий к слайдам

После урока вы сможете

  • Объяснить, что происходит между нажатием Enter и появлением страницы
  • Разобрать адрес сайта на части и прочитать запрос и ответ
  • Отличить фронтенд от бэкенда и узнать на схеме клиент-сервер, API, SPA и микросервисы
  • Открыть DevTools и найти запросы любого сайта

Урок за минуту

  • Веб-приложение состоит из трёх частей: фронтенд в браузере, бэкенд на сервере и база данных
  • Они общаются запросами и ответами по HTTP. Данные передают в формате JSON
  • URL состоит из протокола, домена, пути, параметров и якоря
  • Запрос — это метод и адрес, ответ — статус-код и данные: GET /tasks → 200 OK
  • Всё, что работает в браузере, пользователь может изменить. Проверки прав делает бэкенд

Интернет и веб

Интернет — это сеть: миллиарды компьютеров, соединённых кабелями и Wi-Fi. Поверх сети работают разные сервисы: почта, мессенджеры, онлайн-игры. Веб — один из них: сайты и приложения, которые открываются в браузере.

Фронтенд-разработчик работает с вебом. Всё, что вы сделаете на курсе, откроется в браузере — на ноутбуке и на телефоне.

Веб-приложение из трёх частей

Любое веб-приложение — магазин, почта, банк — устроено как ресторан. Гость сидит в зале и видит меню. Официант приносит заказ на кухню. Повар готовит, продукты берёт со склада.

  • Фронтенд — зал. Интерфейс, который работает в браузере пользователя: кнопки, формы, списки.
  • API — официант. Правила, по которым фронтенд просит у сервера данные.
  • Бэкенд — кухня. Программа на сервере: проверяет, считает, решает. Пользователь её не видит.
  • База данных — склад. Хранит товары, заказы, пользователей.

Этот курс — про зал. Но официанта и кухню вы тоже увидите: в уроке 29 вы напишете маленький сервер сами.

Адрес сайта

У каждой страницы в вебе есть адрес — URL. Он читается слева направо: как связаться, с каким сервером, какую страницу открыть.

  • Протокол — правила общения. https — то же, что http, но с шифрованием.
  • Домен — имя сервера. Людям удобны имена, компьютерам — числа, поэтому домен переводят в IP-адрес.
  • Путь — какую страницу или файл отдать.
  • Параметры — после ?, пары имя=значение через &: ?q=кофе&page=2.
  • Якорь — после #, место на странице. Браузер прокручивает к нему сам, на сервер он не уходит.

Где увидеть полный адрес

Chrome прячет https:// в адресной строке. Щёлкните по адресу — появится целиком.

Что происходит, когда вы открываете сайт

Вы вводите https://shop.ru и нажимаете Enter. Страница появляется через полсекунды, но за это время происходит семь шагов.

Запрос и ответ

Браузер и сервер обмениваются обычным текстом. Так выглядят запрос и ответ, если убрать всё лишнее:

Первая строка запроса — метод и путь. Метод говорит, что сделать:

Метод Что делает Пример
GET Получить открыть каталог, загрузить список задач
POST Создать оформить заказ, отправить сообщение
PUT, PATCH Изменить поменять адрес доставки
DELETE Удалить удалить комментарий

Первая строка ответа — статус-код. По первой цифре понятно, что случилось:

Код Значит Частые примеры
2xx Всё получилось 200 OK, 201 Created — создано
3xx Ищите в другом месте 301 — страница переехала
4xx Ошибка в запросе 404 — не найдено, 401 — нужно войти, 403 — нельзя
5xx Ошибка на сервере 500 — сервер упал

4xx — виноват клиент: опечатка в адресе, нет прав. 5xx — виноват сервер. Фронтенд должен показать понятное сообщение в обоих случаях. Подробно HTTP разберём в уроке 17.

Проверьте сами

В конце урока вы откроете вкладку Network и увидите эти запросы на реальном сайте. Обычно их 50–150 на одну страницу.

Клиент и сервер

Клиент спрашивает, сервер отвечает. Эта схема называется клиент-серверной архитектурой. На ней построен почти весь веб.

Три свойства, которые важно запомнить:

  1. Клиентов много, сервер один. Сайт и мобильное приложение банка ходят в один и тот же бэкенд.
  2. Данные живут на сервере. Поэтому в почте с телефона и с ноутбука одни и те же письма.
  3. Клиенту нельзя доверять. Код фронтенда скачивается к пользователю, и тот может его изменить. Поэтому цены, права и остатки проверяет бэкенд.

«Спрячу кнопку — и никто не удалит чужой заказ»

Скрытая кнопка защищает только от случайного клика. Пользователь откроет DevTools и отправит запрос сам. Проверка «можно ли этому пользователю удалить заказ» всегда делается на сервере.

API — договор между фронтом и бэком

Фронтенд и бэкенд часто пишут разные люди. Чтобы они не мешали друг другу, заранее договариваются: какие адреса есть на сервере, что туда отправлять и что придёт в ответ. Такой договор называется API.

Что делает фронтенд-разработчик

Дизайнер рисует экран. Фронтенд-разработчик делает так, чтобы экран работал у настоящих людей:

  • Вёрстка по макету — страница выглядит как в Figma, на телефоне и на ноутбуке.
  • Поведение — кнопки, формы, фильтры, всплывающие окна.
  • Данные с сервера — запросить, показать, обработать ошибку.
  • Доступность — сайтом можно пользоваться с клавиатуры и программой экранного доступа.
  • Скорость — страница открывается быстро даже на слабом телефоне.

Макет обычно показывает один экран — с данными. А у каждого экрана минимум четыре состояния, и все четыре — работа фронтенда:

Кто есть кто в команде

Роль Что делает Инструменты Результат
Фронтенд-разработчик Интерфейс: вёрстка, логика экранов, запросы к API HTML, CSS, JS, TypeScript, React Работающие экраны в браузере
Бэкенд-разработчик Логика сервера, API, хранение данных Node.js, Python, Go, Java, SQL API и база данных
Фулстек-разработчик И то, и другое, обычно в небольших проектах Всё выше Фича целиком
Мобильный разработчик Приложения для iOS и Android Swift, Kotlin, React Native Приложение в сторе
Дизайнер Как выглядит и как работает интерфейс Figma Макеты экранов
Аналитик Что именно нужно сделать, какие правила Документы, схемы, SQL Требования и задачи
QA (тестировщик) Ищет баги до пользователей Чек-листы, автотесты Отчёты о багах
DevOps Серверы, выкладка, мониторинг Linux, Docker, облака Приложение стабильно работает
Менеджер продукта Решает, что делать в первую очередь и зачем Трекеры задач, метрики План и приоритеты

Путь одной фичи, например кнопки «Добавить в избранное»:

  1. Менеджер решает, что фича нужна. Аналитик описывает правила: сколько товаров можно добавить, что видит гость без аккаунта.
  2. Дизайнер рисует кнопку и её состояния в Figma.
  3. Бэкенд делает адрес API POST /favorites, фронтенд — кнопку, которая туда отправляет запрос.
  4. QA проверяет, DevOps выкладывает новую версию. Это называется деплой.

Где рождается страница: MPA, SPA, SSR

Главный архитектурный вопрос для фронтенда: кто собирает HTML — сервер или браузер. Есть три подхода.

  • MPA — классика. Каждая ссылка загружает новую страницу целиком. Просто и надёжно, но при каждом переходе экран «моргает».
  • SPA — приложение загружается один раз. Дальше JavaScript сам меняет экран, а с сервера берёт только данные в JSON. Работает быстро, как настольная программа.
  • SSR — гибрид. Сервер присылает готовый HTML (быстро показать и хорошо для поисковиков), потом страница работает как SPA.

В курсе вы будете делать SPA на React: сейчас это самый частый формат в вакансиях. SSR (фреймворк Next.js) — логичный следующий шаг после курса.

Монолит и микросервисы

Это про устройство бэкенда. Фронтенду достаточно знать слова, чтобы понимать разговоры в команде.

  • Монолит — весь бэкенд в одном приложении. Так начинают почти все проекты.
  • Микросервисы — бэкенд разбит на сервисы: пользователи, заказы, оплата. Их делают разные команды и выкладывают независимо.

Для фронтенда разницы почти нет: в обоих случаях бэкенд — это набор адресов API.

HTML, CSS и JavaScript

Браузер понимает три языка. У каждого своя задача:

HTML — структура. Что есть на странице.

CSS — внешний вид. Как это выглядит.

JavaScript — поведение. Что происходит при действиях.

Карта курса

Вот что вы соберёте к концу курса. Цифры — номера уроков, где изучается каждая часть.

По дороге будет четыре проекта для портфолио:

Браузеры

Браузеров много, а движков, которые рисуют страницы, — три. Код, который работает в одном браузере, почти всегда работает и в других, но проверять нужно.

Движок Браузеры Где важен
Chromium (Blink) Chrome, Edge, Opera, Яндекс Браузер больше половины пользователей
WebKit Safari все браузеры на iPhone, стандартный на Mac
Gecko Firefox небольшая доля, но свои особенности

На курсе разрабатываем в Chrome — у него самые удобные инструменты. Готовую работу открываем ещё и в Safari: он уже есть на Mac.

DevTools: заглянуть внутрь любого сайта

DevTools есть в каждом браузере. Это главный инструмент фронтенд-разработчика: вы будете открывать его каждый день.

Откройте Chrome, зайдите на любой сайт и нажмите ⌥ Option+⌘ Cmd+I.

Не получается с клавишами?

Щёлкните правой кнопкой (или двумя пальцами по трекпаду) по любому месту страницы → «Просмотреть код». Или меню Chrome: Вид → Разработчикам → Инструменты разработчика.

Вкладка Что показывает Понадобится
Elements HTML и стили страницы, можно менять сегодня, уроки 4–8
Network Все запросы и ответы сегодня, уроки 17–18
Console Ошибки и вывод JavaScript урок 10
Sources Код и точки остановки для отладки урок 14
Application Данные, которые сайт хранит в браузере урок 14

Сегодня нужны первые две.

Elements. Слева — HTML страницы, справа — стили выбранного элемента. Дважды щёлкните по тексту в коде и измените его — страница обновится. Это ваша копия: после обновления страницы (⌘ Cmd+R) всё вернётся.

Network. Откройте вкладку и обновите страницу: ⌘ Cmd+R. Каждая строка — один запрос: имя файла, метод, статус-код, тип, размер. Внизу — сколько всего запросов. Фильтр Fetch/XHR оставит только запросы к API — обычно там JSON.

Язык DevTools

DevTools можно переключить на русский (шестерёнка → Preferences → Language). Но советуем оставить английский: все статьи и ответы на форумах используют английские названия вкладок.

Кем вы станете после курса

В вакансиях разработчиков делят по уровням. После курса вы — junior: знаете основу и делаете задачи сами, со старшим коллегой рядом.

Уровень Опыт Как работает
Junior до 1–2 лет делает понятные задачи, спрашивает, учится на ревью
Middle 2–4 года делает фичу целиком сам, помогает джунам
Senior от 4–5 лет решает, как устроить систему, отвечает за качество

Годы — ориентир, а не правило. Уровень определяют задачи, которые вы решаете без помощи. Как искать первую работу, разберём в уроке 33.

Как учиться на курсе

Каждый урок проходит по одному циклу:

  1. Текст урока — читать с открытым редактором, повторять примеры. Около 1 часа.
  2. Слайды — занятие с ментором: разбор, вопросы, живой код.
  3. Квиз — 5 минут, проверка, что главное усвоено.
  4. Задания — от лёгкого к сложному. Застряли больше чем на 30 минут — пишите ментору.
  5. Ревью — ментор проверяет задания по чек-листу. До урока 9 работы сдаются файлом, потом — через GitHub.

Правила работы с AI-ассистентами

AI (ChatGPT, Claude и другие) — отличный репетитор и плохой решатель домашек.

  • Можно: попросить объяснить непонятное, дать подсказку без решения, найти ошибку в вашем коде и объяснить её.
  • Нельзя: генерировать решение задания целиком. Вы получите зачёт, но не навык, и это вскроется на собеседовании.
  • Правило: каждую строку сданного кода вы должны уметь объяснить ментору.

Частые заблуждения

«Фронтенд — это чтобы было красиво»

Красиво делает дизайнер. Фронтенд отвечает за то, чтобы интерфейс работал: загружал данные, обрабатывал ошибки, был быстрым и удобным на любом экране.

«Сайт хранится у меня в браузере»

В браузере — только копия интерфейса. Данные лежат на сервере, поэтому они одинаковые на всех устройствах.

«Без математики и английского в программирование не попасть»

Для фронтенда хватает школьной арифметики. Английский нужен на уровне «читаю документацию с переводчиком» — он подтянется сам, названия в коде английские.

«Надо сначала выучить всё про HTML, потом переходить к CSS»

Никто не знает всё. Профессионалы постоянно читают документацию. Цель — понимать, как устроено, и уметь быстро найти детали.

Квиз: 9 вопросов
  1. 1. Где выполняется код фронтенда?
    Код фронтенда скачивается к пользователю и выполняется в его браузере. Поэтому его можно посмотреть и изменить.
  2. 2. Что делает DNS?
    DNS — «телефонная книга»: по имени shop.ru находит адрес 185.12.3.4. Шифрование — это TLS, буква S в HTTPS.
  3. 3. Какая часть адреса https://shop.ru/catalog?sort=price#reviews не уходит на сервер?
    Якорь после решётки нужен только браузеру — чтобы прокрутить к месту на странице. Путь и параметры сервер получает.
  4. 4. Сервер ответил 404. Что это значит?
    4xx — ошибка на стороне клиента, 404 — «не найдено». Если бы сервер упал, был бы 5xx, например 500.
  5. 5. Пользователь через DevTools показал скрытую кнопку «Скидка 90%» и нажал её. Что должно защитить магазин?
    Клиенту нельзя доверять. Всё в браузере пользователь может изменить. Права и цены проверяет сервер.
  6. 6. Что такое API в веб-разработке?
    API — это интерфейс между программами. Например, GET /tasks возвращает список задач в JSON.
  7. 7. Чем SPA отличается от MPA?
    В MPA каждый переход — новая HTML-страница с сервера. В SPA JavaScript меняет экран без перезагрузки.
  8. 8. На странице кнопка есть и работает, но выглядит как серый прямоугольник. Какой части не хватает?
    HTML дал кнопку, JavaScript — поведение. За внешний вид отвечает CSS.
  9. 9. Вы открыли вкладку Network и обновили страницу. Что вы увидите?
    Network показывает запросы и ответы. Код сервера и базу данных из браузера не видно — они на сервере.

Как сделать скриншот на Mac

⌘+⇧+4 — выделить область, ⌘+⇧+4, затем Пробел — снять окно целиком. Если держать ещё и ⌃ Control, скриншот попадёт в буфер обмена — его можно сразу вставить в поле ответа: ⌘+V.
