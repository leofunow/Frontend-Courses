## Что такое HTML

[[HTML]] — язык разметки. Вы берёте обычный текст и помечаете: вот заголовок, вот абзац, вот список. Браузер читает пометки и строит страницу.

Попробуйте: слева — разметка, справа — что показывает браузер. Уберите теги у списка — браузер склеит пункты в одну строку.

:::sandbox Текст и разметка height=340
```html
<h1>Кофейня «Зерно»</h1>
<p>Варим кофе с 8 утра.</p>
<h2>Меню</h2>
<ul>
  <li>Эспрессо — 150 ₽</li>
  <li>Капучино — 220 ₽</li>
  <li>Какао — 200 ₽</li>
</ul>
```
:::

HTML не отвечает за цвета, шрифты и расположение — это [[CSS]] (урок {{n:css-basics}}). HTML отвечает только за смысл и порядок.

## Анатомия тега

Почти всё в HTML — [[элемент|элементы]]: открывающий [[тег]], содержимое, закрывающий тег. [[Атрибут|Атрибуты]] пишутся внутри открывающего тега и уточняют его.

:::diagram id=tag-anatomy
type: flow
caption: "Ссылка на страницу «О нас» — один элемент a"
items:
  - {title: "`<a href=\"about.html\">`", text: "открывающий тег с атрибутом href", kind: accent, icon: false}
  - {title: О нас, text: "содержимое: что видит пользователь", kind: muted, icon: false}
  - {title: "`</a>`", text: "закрывающий тег: косая черта перед именем", kind: accent, icon: false}
:::

Атрибут записывается как `имя="значение"`. У одного тега может быть несколько атрибутов через пробел:

```html
<a href="https://ya.ru" target="_blank">Яндекс</a>
<img src="img/logo.png" alt="Логотип кофейни">
```

У некоторых тегов нет содержимого и закрывающего тега: `<img>`, `<br>`, `<meta>`, `<link>`, `<input>`.

**Вложенность.** Элементы вкладываются друг в друга, как коробки: что открыли последним — закрываем первым.

:::cols
**Правильно**

```html
<p>Кофе <strong>очень</strong> горячий</p>
```
+++
**Неправильно: теги перекрещиваются**

```html
<p>Кофе <strong>очень</p> горячий</strong>
```
:::

## Каркас страницы

Каждая страница начинается одинаково. Этот каркас Emmet вставляет по `!` и <kbd>Tab</kbd> (урок {{n:vscode}}):

```html title="index.html"
<!doctype html>                  <!-- это HTML-документ современного стандарта -->
<html lang="ru">                 <!-- корень страницы, язык — русский -->
  <head>                         <!-- служебное: на странице не видно -->
    <meta charset="utf-8">       <!-- кодировка: чтобы кириллица не превратилась в «кракозябры» -->
    <meta name="viewport" content="width=device-width, initial-scale=1.0">  <!-- для телефонов -->
    <title>Кофейня «Зерно»</title>  <!-- текст на вкладке браузера -->
  </head>
  <body>                         <!-- всё, что видно на странице -->
    <h1>Кофейня «Зерно»</h1>
  </body>
</html>
```

:::diagram id=document-tree
type: tree
caption: "Документ — это дерево. Такое же дерево вы увидите во вкладке Elements в DevTools"
items:
  - name: html
    note: "`lang=\"ru\"`"
    items:
      - name: head
        note: служебное
        items:
          - {name: meta, note: charset}
          - {name: meta, note: viewport}
          - {name: title, note: текст вкладки}
      - name: body
        mark: true
        note: видимое
        items:
          - {name: h1}
          - {name: p}
:::

:::tip Язык страницы
Emmet ставит `lang="en"`. Поменяйте на `lang="ru"`: так программы экранного доступа читают текст с правильным произношением, а Biome перестанет напоминать об ошибке.
:::

## Что ещё кладут в head

В `<head>` лежит всё, что не видно на странице, но нужно браузеру и поисковикам. Каркас Emmet даёт первые три строки, остальные добавляют сами:

```html title="index.html"
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Кофейня «Зерно» — кофе на Лесной</title>
  <meta name="description" content="Кофейня у метро Белорусская: свежая обжарка, завтраки с 8 утра.">
  <link rel="icon" href="favicon.svg">
</head>
```

| Строка | Зачем |
|---|---|
| `charset` | Кодировка. Без неё кириллица превращается в «кракозябры» |
| `viewport` | Страница под ширину телефона, подробно — в уроке {{n:responsive}} |
| `<title>` | Текст вкладки и заголовок в поисковой выдаче |
| `description` | Описание под заголовком в поисковой выдаче. Одно-два предложения |
| `<link rel="icon">` | Значок на вкладке — favicon. Удобнее всего SVG |

Позже здесь же появится `<link rel="stylesheet">` — подключение стилей из урока {{n:css-basics}}.

## Заголовки и абзацы

Заголовки бывают шести уровней: от `<h1>` до `<h6>`. Уровень выбирают по смыслу, как в оглавлении книги, а не по размеру шрифта: размер настроим в CSS.

:::diagram id=headings-outline
type: tree
caption: "Заголовки страницы — это оглавление. Уровни не перепрыгивают: после h2 идёт h3, а не h4"
items:
  - name: h1
    note: Рецепт блинов
    items:
      - name: h2
        note: Ингредиенты
      - name: h2
        note: Приготовление
        items:
          - {name: h3, note: Тесто}
          - {name: h3, note: Жарка}
:::

:::sandbox Заголовки и текст height=380
```html
<h1>Рецепт блинов</h1>
<p>Тонкие блины на молоке. Готовятся за <strong>30 минут</strong>.</p>

<h2>Ингредиенты</h2>
<p>Всё есть в ближайшем магазине.</p>

<h2>Приготовление</h2>
<p>Главное — <em>не торопиться</em> с первым блином.</p>
```
:::

| Тег | Смысл |
|---|---|
| `<h1>` | Главный заголовок страницы. Один на страницу |
| `<h2>`–`<h6>` | Подзаголовки: разделы, подразделы |
| `<p>` | Абзац |
| `<strong>` | Важное, по умолчанию жирное |
| `<em>` | Смысловое ударение, по умолчанию курсив |
| `<br>` | Перенос строки внутри абзаца. Нужен редко: в адресах и стихах |
| `<hr>` | Смысловой разрыв между частями текста, по умолчанию — линия |

## Выделение в тексте

Внутри абзаца отдельные слова тоже можно разметить. Каждый тег сообщает, **зачем** слово выделено, а браузер показывает это по-своему:

:::shot img/html-text-format.webp width=640
Код слева, результат справа. Всё это — строчные элементы: живут внутри абзаца
:::

Есть пары, которые выглядят одинаково: `<strong>` и `<b>` — жирный, `<em>` и `<i>` — курсив. Разница в смысле. `strong` — «это важно», программа экранного доступа выделит его голосом. `b` — просто жирный без смысла. Берите `strong` и `em`, а просто жирный или курсив для красоты делайте в CSS.

**Специальные символы.** Знаки `<` и `>` браузер считает началом тега. Чтобы показать их как текст, пишут коды:

| Код | Символ | Когда |
|---|---|---|
| `&lt;` `&gt;` | < > | показать тег как текст |
| `&amp;` | & | сам амперсанд |
| `&nbsp;` | неразрывный пробел | `100&nbsp;₽` — число и рубль не разорвутся по строкам |

Кавычки «ёлочки», тире и ₽ пишите прямо: кодировка utf-8 их понимает.

## Списки

Два вида списков: маркированный `<ul>` — порядок не важен, нумерованный `<ol>` — порядок важен. Каждый пункт — `<li>`. Внутри пункта может быть другой список.

:::sandbox Списки height=400
```html
<h2>Ингредиенты</h2>
<ul>
  <li>Молоко — 500 мл</li>
  <li>Яйца — 2 шт.</li>
  <li>Мука — 200 г</li>
</ul>

<h2>Приготовление</h2>
<ol>
  <li>Смешайте яйца и молоко.</li>
  <li>Добавьте муку и перемешайте.</li>
  <li>Жарьте на горячей сковороде.</li>
</ol>
```
:::

Третий вид — список определений `<dl>`: пары «термин — описание». Подходит для глоссария, характеристик товара, меню с описаниями.

```html
<dl>
  <dt>Эспрессо</dt>
  <dd>30 мл крепкого кофе</dd>
  <dt>Раф</dt>
  <dd>Эспрессо, сливки и ванильный сахар</dd>
</dl>
```

`dt` — термин, `dd` — описание. У одного термина может быть несколько `dd`.

## Ссылки

Ссылка — тег `<a>` с атрибутом `href`: куда вести.

```html
<a href="https://developer.mozilla.org">MDN</a>       <!-- другой сайт: полный адрес -->
<a href="about.html">О нас</a>                         <!-- страница вашего сайта -->
<a href="#contacts">Контакты</a>                       <!-- место на этой же странице -->
<a href="mailto:hello@zerno.ru">Напишите нам</a>       <!-- письмо -->
<a href="tel:+79990000000">Позвонить</a>              <!-- звонок с телефона -->
```

Внешнюю ссылку можно открыть в новой вкладке: `target="_blank"`. Добавляйте к нему `rel="noopener"` — это защищает вашу страницу от чужой.

Ссылка `#contacts` ведёт к элементу с атрибутом `id="contacts"` на той же странице. Так делают оглавления.

## Пути к файлам

Пути в `href` и `src` работают как в Терминале (урок {{n:setup}}): от текущего файла. Пусть сайт устроен так:

:::diagram id=site-paths
type: tree
caption: "Папка сайта. Выделен файл, из которого ставим ссылки"
items:
  - name: zerno
    items:
      - {name: index.html, mark: true, note: "пишем ссылки отсюда"}
      - {name: about.html, note: "`href=\"about.html\"`"}
      - name: img
        items:
          - {name: logo.png, note: "`src=\"img/logo.png\"`"}
      - name: menu
        items:
          - {name: coffee.html, note: "`href=\"menu/coffee.html\"`"}
:::

А из `menu/coffee.html` путь к логотипу другой: сначала подняться на уровень выше — `../img/logo.png`.

:::mistake Абсолютный путь с вашего компьютера
`src="/Users/mary/dev/zerno/img/logo.png"` работает только на вашем Mac. У всех остальных — и на GitHub Pages — картинки не будет. Пишите пути от текущего файла.
:::

## Картинки

Картинка — тег `<img>`: `src` — путь к файлу, `alt` — описание.

```html
<img src="img/pancakes.jpg" alt="Стопка блинов со сметаной" width="400" height="300">
```

[[Альтернативный текст]] в `alt` читают программы экранного доступа. Его же браузер показывает, если картинка не загрузилась. Пишите, что изображено, коротко и по делу:

| alt | Оценка |
|---|---|
| `alt="Стопка блинов со сметаной"` | хорошо: понятно без картинки |
| `alt="картинка"` | плохо: ничего не сообщает |
| `alt=""` | правильно для чисто декоративной картинки |
| без `alt` | ошибка: Biome подчеркнёт |

| Формат | Для чего |
|---|---|
| `.jpg` | Фотографии |
| `.png` | Картинки с прозрачностью, скриншоты |
| `.svg` | Логотипы и иконки: чёткие при любом размере |
| `.webp` | Современная замена jpg и png, весит меньше |

Картинку с подписью оборачивают в `<figure>`, а подпись кладут в `<figcaption>`. Так браузер и программы экранного доступа понимают, что подпись относится к этой картинке:

```html
<figure>
  <img src="img/latte.jpg" alt="Латте с рисунком в виде листа">
  <figcaption>Латте-арт от бариста Анны</figcaption>
</figure>
```

:::mistake Logo.PNG и logo.png — разные файлы
На вашем Mac регистр букв в именах файлов не важен, а на сервере, например на GitHub Pages, — важен. Картинка, которая работает у вас, пропадёт после публикации. Называйте файлы маленькими латинскими буквами без пробелов: `hero-image.jpg`.
:::

## Раскрывающийся блок и встроенная страница

**`<details>`** — блок, который открывается по щелчку. `<summary>` — видимая часть. Годится для частых вопросов и подсказок. JavaScript не нужен.

:::sandbox Частые вопросы height=260
```html
<details>
  <summary>Можно ли с собакой?</summary>
  <p>Да, на веранде. Воду для собаки нальём сами.</p>
</details>
<details open>
  <summary>Есть ли растительное молоко?</summary>
  <p>Овсяное, миндальное и кокосовое — без доплаты.</p>
</details>
```
:::

Атрибут `open` открывает блок сразу. Щёлкните по вопросам — они сворачиваются и разворачиваются.

**`<iframe>`** — окно с другой страницей внутри вашей. Так вставляют карту, видео с YouTube или VK Видео. Код обычно даёт сам сервис кнопкой «Поделиться → Встроить»:

```html
<iframe src="https://yandex.ru/map-widget/v1/?ll=37.58,55.77&z=16"
        width="600" height="400" title="Кофейня на карте" loading="lazy"></iframe>
```

`title` описывает, что внутри окна, — для программ экранного доступа. `loading="lazy"` — грузить, только когда окно доскроллили.

## Семантическая разметка

[[Семантическая разметка|Семантические теги]] делят страницу на части по смыслу. Выглядят они как обычные блоки, но браузер, поисковик и программа экранного доступа понимают, где шапка, где меню, а где основное содержимое.

:::shot img/semantic-regions.webp
Страница кофейни. Подписаны семантические теги
:::

```html
<body>
  <header>
    <strong>Зерно</strong>
    <nav>
      <a href="menu.html">Меню</a>
      <a href="about.html">О нас</a>
    </nav>
  </header>
  <main>
    <article>
      <h1>Кофе, который хочется повторить</h1>
      <p>Обжариваем зерно сами каждую неделю.</p>
    </article>
    <aside>Акция недели</aside>
  </main>
  <footer>© Кофейня «Зерно», 2026</footer>
</body>
```

| Тег | Что внутри |
|---|---|
| `<header>` | Шапка: логотип, название, иногда меню |
| `<nav>` | Главная навигация — набор ссылок |
| `<main>` | Основное содержимое. Один на страницу |
| `<section>` | Раздел с собственным заголовком |
| `<article>` | Самостоятельный материал: статья, карточка товара, пост |
| `<aside>` | Дополнительное: боковая колонка, врезка |
| `<footer>` | Подвал: контакты, копирайт |
| `<address>` | Контакты: адрес, телефон, почта. Обычно в подвале |
| `<div>` и `<span>` | Безликие контейнеры, когда подходящего по смыслу тега нет |

:::tip Как выбрать тег
Спросите себя, как бы вы назвали этот кусок страницы вслух. «Шапка» — `header`. «Меню» — `nav`. «Просто обёртка, чтобы покрасить» — `div`.
:::

**`section` или `article`?** Мысленно вырежьте кусок и перенесите на другой сайт. Понятен сам по себе — пост, отзыв, карточка товара — это `article`. Имеет смысл только на этой странице, как раздел «Меню» внутри лендинга, — `section`. В обоих случаях внутри должен быть заголовок.

Три инструмента вы уже знаете:

1. **Biome** в VS Code подчеркнёт `alt` без описания, пропущенный `lang`, пустые ссылки. То же покажет команда в терминале:

2. **DevTools → Elements** (<kbd>⌥</kbd>+<kbd>⌘</kbd>+<kbd>I</kbd>) покажет дерево, которое построил браузер. Если тег не закрыт, дерево будет не таким, как вы ожидали.
3. **Проверки на странице** в домашних заданиях: плашка в правом нижнем углу.

## Частые ошибки

:::mistake Заголовок выбран по размеру
`<h3>` вместо `<h2>`, потому что «так меньше». Уровень — это смысл, размер поменяем в CSS.
:::

:::mistake Всё на div
`<div class="header">` вместо `<header>`. Работает, но программы экранного доступа и поисковики не поймут структуру.
:::

:::mistake Текст вне тегов
Текст прямо в `<body>` или в `<ul>` без `<li>`. Браузер покажет, но разметка сломана. Каждый кусок текста — внутри подходящего тега.
:::

## Шпаргалка

| Задача | Тег |
|---|---|
| Главный заголовок | `<h1>` |
| Подзаголовок | `<h2>`…`<h6>` |
| Абзац | `<p>` |
| Важное / ударение | `<strong>` / `<em>` |
| Список без порядка / по порядку | `<ul>` / `<ol>` + `<li>` |
| Ссылка | `<a href="…">` |
| Картинка / с подписью | `<img src="…" alt="…">` / `<figure>` + `<figcaption>` |
| Раскрывающийся блок | `<details>` + `<summary>` |
| Шапка / меню / подвал | `<header>` / `<nav>` / `<footer>` |
| Основное / раздел / материал | `<main>` / `<section>` / `<article>` |
| Обёртка без смысла | `<div>`, `<span>` в строке |

## Квиз

:::quiz
- q: За что отвечает HTML?
  options:
    - За цвета и шрифты
    - За структуру и смысл содержимого страницы
    - За поведение кнопок
    - За хранение данных на сервере
  answer: 1
  why: HTML говорит, что на странице есть. Внешний вид — CSS, поведение — JavaScript.
- q: 'Что в `<a href="about.html">О нас</a>` является атрибутом?'
  options:
    - "`a`"
    - '`href="about.html"`'
    - "`О нас`"
    - "`</a>`"
  answer: 1
  why: Атрибут — имя и значение внутри открывающего тега. `a` — имя тега, «О нас» — содержимое.
- q: Где на странице будет виден текст из `<title>`?
  options:
    - В самом верху страницы крупным шрифтом
    - На вкладке браузера и в поисковой выдаче
    - Нигде
    - В подвале
  answer: 1
  why: "`<title>` лежит в `<head>` — служебной части. На самой странице он не показывается."
- q: Сколько `<h1>` должно быть на странице?
  options:
    - Сколько угодно
    - Один
    - Ни одного
    - По одному в каждом абзаце
  answer: 1
  why: h1 — главный заголовок страницы. Разделы ниже размечают h2–h6.
- q: Какой список подходит для шагов рецепта?
  options:
    - "`<ul>`"
    - "`<ol>`"
    - Абзацы `<p>` с номерами вручную
    - "`<nav>`"
  answer: 1
  why: В рецепте порядок важен, поэтому нумерованный список ol. Номера браузер поставит сам.
- q: 'Файл `menu/coffee.html` ссылается на картинку `img/logo.png` в корне сайта. Какой путь верный?'
  options:
    - "`img/logo.png`"
    - "`../img/logo.png`"
    - "`/Users/mary/dev/zerno/img/logo.png`"
    - "`logo.png`"
  answer: 1
  why: "Из папки menu нужно подняться на уровень выше: `..`, а затем зайти в img."
- q: Какой alt лучше для фотографии блинов в рецепте?
  options:
    - '`alt="картинка"`'
    - '`alt="Стопка блинов со сметаной"`'
    - '`alt="IMG_2034.jpg"`'
    - alt не нужен
  answer: 1
  why: alt должен объяснять, что на картинке, человеку, который её не видит.
- q: Чем `<strong>` отличается от `<b>`?
  options:
    - Ничем, это синонимы
    - "`strong` означает «важно», `b` — просто жирный текст без смысла"
    - "`b` жирнее"
    - "`strong` устарел"
  answer: 1
  why: Выглядят одинаково, но strong несёт смысл, и программа экранного доступа его подчеркнёт. Для жирного «для красоты» есть CSS.
- q: Каким тегом разметить главное меню сайта?
  options:
    - "`<div class=\"menu\">`"
    - "`<nav>`"
    - "`<footer>`"
    - "`<menu-list>`"
  answer: 1
  why: nav — семантический тег для основной навигации. div не несёт смысла, menu-list не существует.
- q: Картинка видна на вашем Mac, но пропала на GitHub Pages. Файл называется `Logo.PNG`, в коде — `logo.png`. Почему?
  options:
    - GitHub Pages не поддерживает PNG
    - На сервере регистр букв в имени файла важен
    - Нужно добавить alt
    - Картинка слишком большая
  answer: 1
  why: macOS не различает регистр в именах файлов, а серверы различают. Называйте файлы строчными буквами.
