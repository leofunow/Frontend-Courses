## Воркшоп: публикуем сайт кофейни (20 мин)

**На слайде:** четыре шага: коммиты, Git Graph, GitHub, pull request.

**Подготовить заранее:** папка `workshop-html` с сайтом кофейни из уроков {{n:html-basics}}–{{n:responsive}}, ещё без Git. В Chrome вы вошли в свой GitHub. Расширение Git Graph установлено. В Терминале выполнен `git config --global --list` — там ваше имя.

**Показать вживую:**
1. **Репозиторий.** VS Code → File → Open Folder → `workshop-html`. Слева Source Control (третья иконка) → **Initialize Repository**.
   - У всех файлов буква **U** — Git их видит, но не хранит.
   - В проводнике New File → `.gitignore`, одна строка `.DS_Store`, <kbd>⌘</kbd>+<kbd>S</kbd>. Если в папке был `.DS_Store`, он пропал из списка изменений.
2. **Первый коммит.** Наведите на заголовок Changes → **+** (Stage All Changes). Файлы переехали в Staged Changes.
   - В поле сообщения: «Добавить сайт кофейни» → <kbd>⌘</kbd>+<kbd>Enter</kbd>. Список изменений опустел.
3. **Второй коммит.** В `index.html` поменяйте текст `h1` → <kbd>⌘</kbd>+<kbd>S</kbd>.
   - Слева от строки в редакторе появилась синяя полоса — строка изменена. Щёлкните по ней — видно, что было.
   - В Source Control у файла **M**. Щелчок по файлу — сравнение слева и справа.
   - Сообщение «Изменить заголовок главной» → <kbd>⌘</kbd>+<kbd>Enter</kbd>.
4. **Git Graph.** Кнопка **Git Graph** в строке состояния внизу.
   - Два коммита, метка `main` у верхнего. Щёлкните по нижнему коммиту → внизу список файлов → щелчок по `index.html` — что было в первом коммите.
5. **На GitHub.** Source Control → **Publish Branch** → **Publish to GitHub public repository**.
   - В браузере Authorize → вернитесь в VS Code. Внизу справа уведомление со ссылкой → **Open on GitHub**.
   - На GitHub: список файлов, над ним ссылка «2 commits» → щёлкните коммит — изменения на GitHub выглядят так же, как в VS Code.
   - В Git Graph у коммита появилась метка `origin/main`.
6. **GitHub Pages.** В репозитории Settings → слева Pages → Branch: `main`, `/ (root)` → Save.
   - Вкладка Actions: идёт «pages build and deployment». Через минуту вернитесь в Settings → Pages — сверху адрес. Откройте его, потом с телефона.
7. **Pull request.** В VS Code щёлкните `main` в строке состояния → Create new branch → `lesson-09`.
   - Поменяйте текст в подвале, закоммитьте «Обновить адрес в подвале» → **Publish Branch**.
   - На GitHub жёлтая плашка → **Compare & pull request** → заголовок и пара строк описания → **Create pull request**.
   - Вкладка Files changed: наведите на строку → синий **+** → комментарий «Здесь лучше тег address» → Add single comment. Так ментор будет комментировать решения.
   - **Merge pull request** → Confirm merge. В VS Code щёлкните `lesson-09` внизу → переключитесь на `main` → **Sync Changes**. В Git Graph видно, как ветка влилась в `main`.
8. **Ошибка нарочно.** На GitHub откройте `index.html` → карандаш → поменяйте слово → Commit changes. В VS Code поменяйте другой файл, закоммитьте и сделайте push через Терминал (<kbd>⌃</kbd>+<kbd>`</kbd>, `git push`) — «Updates were rejected».
   - Прочитайте ошибку вслух: на GitHub есть то, чего нет у нас. `git pull` → `git push` — прошло.

**Рассказать:** ученик повторит всё это в домашке: первое задание — шаги 1–4, второе — 5–6, третье — шаг 7 на своём репозитории домашних заданий. Свой pull request одобрить нельзя, поэтому Approve ученик увидит в первой проверке.
