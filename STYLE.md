# Руководство по урокам

Правила для всех, кто пишет или правит уроки курса (людей и AI-агентов). Эталон — урок 1: `src/lessons/01-intro/`.

## Главное

1. **Коротко.** Каждое предложение либо объясняет, либо показывает. Если его можно удалить без потери смысла — удаляем.
2. **Сначала пример, потом правило.** Абстракция без примера не допускается.
3. **Каждая идея — с картинкой или кодом.** Каждый раздел `##` содержит схему, код, песочницу или таблицу.
4. **Ученик — взрослый, с полного нуля, на macOS.** Не «очевидно», не «как все знают». Команды — для Терминала macOS (zsh), сочетания клавиш — с ⌘. Программы ставим с официальных сайтов, без Homebrew.
5. **Язык — русский.** Термин при первом появлении: русское слово и английский оригинал (через глоссарий). Код и имена — по-английски, комментарии в коде — по-русски.

## Объём

| Что | Лимит |
|---|---|
| Текст урока (без кода, схем, квиза и заданий) | ≤ 2500 слов |
| Раздел `##`: вводный текст до примера | ≤ 120 слов |
| Предложение | ≤ 25 слов |
| Цели урока | 3–4 пункта |
| «Урок за минуту» | 3–5 пунктов |
| Квиз | 6–10 вопросов |
| Задания | 3–6, от лёгкого к сложному |
| Слайды | 12–36; урок-витрина с разделителями частей — ближе к 36 |
| Сценарий | раздел на каждый слайд, ≈ 90 минут |
| «Читать дальше» | 2–5 ссылок: сначала metanit.com, потом MDN и документация |

`npm run lint:content` проверяет лимиты и стоп-слова.

## Стоп-слова

Не используем: «давайте разберёмся», «важно отметить», «стоит отметить», «следует отметить», «в современном мире», «как известно», «не секрет, что», «таким образом», «в заключение», «итак», «данный», «является одним из», «играет важную роль», «огромное количество», «мощный инструмент», «погрузимся», «окунёмся», «в этом уроке мы», «безусловно», «на самом деле», «просто» (когда это не так).

## Структура урока

Файлы: `src/lessons/NN-id/lesson.md`, `slides.md` и `script.md`. Номер, название и модуль берутся из `src/syllabus.yml`: у каждого урока постоянный `id`, а номер считается по порядку.

**Номера уроков в тексте не пишем цифрами.** Пишем `{{n:id}}` — сборка подставит актуальный номер: «в уроке {{n:express}}» → «в уроке 28». Если урок вставят в середину программы, все номера пересчитаются. `{{count}}` — число уроков со словом: «31 урок». Неизвестный id — ошибка сборки, цифра после слова «урок» — ошибка `lint:content`.

```md
---
duration: 90 минут теории, 1,5–2 часа заданий
goals:
  - Глагол + результат: «Создать…», «Объяснить…», «Найти…»
summary:
  - Главная мысль урока одной строкой
readMore:
  - title: MDN — …
    url: https://developer.mozilla.org/ru/…
---

## Раздел 1 … ## Раздел N     ← теория: идея → пример → песочница
## Частые ошибки               ← :::mistake-блоки
## Шпаргалка                   ← таблица или код
## Квиз                        ← :::quiz
## Задания                     ← :::task
```

Порядок внутри раздела: 1–3 предложения идеи → схема или код → разбор, что произошло → песочница или «попробуйте сами».

## Блоки

### Выноски

```md
:::tip Заголовок
Совет.
:::
```

- `:::tip` — совет;
- `:::note` — заметка;
- `:::important` — важно;
- `:::mistake` — частая ошибка;
- `:::mac` — особенность macOS.

Без заголовка подставляется название по умолчанию.

### Термины

`[[термин]]` или `[[термин|словоформа]]`, например `[[сервер|сервере]]`. Термин должен быть в `src/glossary.yml`, иначе сборка упадёт. Отмечаем только первое появление термина в уроке.

### Код

Блоки кода с языком: `html`, `css`, `js`, `ts`, `tsx`, `json`, `bash` (Терминал), `http`, `text`. Имя файла указывается так: ` ```js title="app.js" `. Команды терминала — всегда `bash`, подпись у блока будет «Терминал».

### Песочница

````md
:::sandbox Заголовок height=320
```html
<button>Купить</button>
```
```css
button { color: red; }
```
```js
console.log('привет');
```
:::
````

После песочницы — 2–3 эксперимента: «замените…», «удалите…», «что будет, если…».

### Колонки

`:::cols`, внутри колонки разделяются строкой `+++`.

### Скриншот

````md
:::shot img/имя.webp width=600
Подпись под картинкой
:::
````

Картинки лежат в `img/` урока и снимаются командой `npm run screenshots -- фильтр` по описанию в `screenshots.yml` урока:

```yaml
- file: имя.webp
  url: examples/page.html          # или https://…; локальные пути — от папки урока
  viewport: [1280, 800]
  mobile: true                     # телефон: учитывается meta viewport
  steps: [{click: "…"}, {press: Meta+KeyP}, {type: "…"}, {wait: 500}]
  hide: ["[data-runner]"]
  marks: [{selector: ".sidebar", label: 1, side: inset}]   # номер-метка на элементе
  clip: {selector: ".wrap", pad: 16}                         # или {x, y, width, height}
```

Наглядные примеры для скриншотов — отдельные страницы в `examples/` урока. Эталон задания — рендер решения из `mentor/`. Интерфейс VS Code — vscode.dev или настоящее окно VS Code в папке `~/tmp/code-courses` (для расширений, которым нужен локальный Git, например Git Graph).

### Терминал

````md
:::terminal title="dev — zsh" caption="Подпись"
mary@MacBook ~ % ls
dev  Desktop  Documents
! zsh: command not found: nmp
:::
````

Окно Терминала macOS. Строки с приглашением распознаются сами, `! ` — строка с ошибкой, `[1]` — номер-метка.

### Спойлер

`:::details Подсказка`.

### Квиз

```md
:::quiz
- q: Вопрос?
  options:
    - Вариант
    - Правильный вариант
  answer: 1          # номер с нуля
  why: Почему так. Показывается после ответа.
:::
```

Неправильные варианты — правдоподобные заблуждения, а не шутки. `why` объясняет и правильный ответ, и главную ошибку.

### Задание

```md
:::task Название level=2 time="30 мин"
Что сделать, по шагам.

:::answer text Вопрос, на который ученик отвечает текстом
:::answer image Какой скриншот прикрепить
:::answer table Название таблицы cols="Сайт|Запросов|Статус" rows="ya.ru|github.com"

- [ ] Критерий, который ученик отмечает сам
:::
```

`level`: 1 — лёгкое, 2 — среднее, 3 — сложное. Каждое задание заканчивается чек-листом результата.

`:::answer` — поле для ответа, однострочный блок без закрывающего `:::`:
- `text` — текст; `rows=N` — высота поля, `placeholder="…"` — подсказка;
- `image` — скриншоты: выбрать файл, вставить <kbd>⌘</kbd>+<kbd>V</kbd>, перетащить; по щелчку открываются целиком;
- `table` — таблица: `cols` — столбцы, `rows` — подписи строк через `|` или число пустых строк (тогда есть кнопка «Добавить строку»).

Ответы хранятся в браузере ученика (IndexedDB) и не пропадают после перезапуска. Внизу урока с заданиями сама появляется кнопка «Сформировать отчёт»: ZIP с `README.md`, файлом `task-N.md` на задание и картинками. Не пишите в подписи поля `слово="…"` — это прочитается как параметр.

### Клавиши

Сочетания пишем по-маковски, через `<kbd>`: <kbd>⌘ Cmd</kbd>+<kbd>R</kbd>. В модуле 0 — с названием клавиши (`⌘ Cmd`, `⌥ Option`, `⇧ Shift`, `⌃ Control`), дальше можно только символ: <kbd>⌘</kbd>+<kbd>R</kbd>.

## Схемы

Схемы описываются в YAML. Картинки и SVG с координатами **не используем**: сборщик сам превращает описание в HTML-блоки, которые растягиваются под текст и перестраиваются на узком экране. Поэтому текст не может вылезти за рамку.

````md
:::diagram id=имя
type: flow | rows | sequence
caption: Подпись под схемой
steps: [...]      # необязательно: пошаговый показ
…
:::
````

`id` нужен, чтобы вставить ту же схему в слайды: `:::use имя`.

### flow — ряд блоков со стрелками

```yaml
type: flow
items:
  - {title: Фронтенд, text: интерфейс, kind: front}
  - {arrow: right, label: запрос}         # right | left | both | pair
  - {arrow: pair, label: запрос, back: ответ}
  - group: Сервер                          # группа блоков в рамке
    kind: back
    cols: 2
    items:
      - {title: Express, badge: "27"}
```

### rows — несколько рядов с подписями слева

```yaml
type: rows
rows:
  - label: MPA
    sub: пояснение
    items: [ …как во flow… ]
    note: подпись под рядом
```

### sequence — последовательность запросов

```yaml
type: sequence
actors:
  - {id: b, title: Браузер, kind: front}
  - {id: s, title: Сервер, kind: back}
messages:
  - {from: b, to: s, label: Запрос, code: GET /, step: 1}
  - {from: s, to: b, label: Ответ, dashed: true, step: 2}
  - {note: Страница на экране, at: b, step: 3}
steps:
  - Подпись шага 1
  - Подпись шага 2
  - Подпись шага 3
```

Код внутри схем пишите в обратных кавычках: `` note: "`href=\"a.html\"`" ``. Иначе типограф заменит прямые кавычки на «ёлочки».

**Поля узла:**
- `title` — название;
- `text` — пояснение;
- `code` — моноширинная вставка;
- `badge` — номер урока;
- `kind` — цвет по роли;
- `icon` — любая иконка [Octicons](https://primer.style/octicons) или `false`;
- `step` — номер шага.

**Значения `kind`:**

| `kind` | Цвет | Для чего |
|---|---|---|
| `plain` | нейтральный | прочее |
| `muted` | серый | аналогии, внешнее |
| `front` | синий | браузер, фронтенд |
| `back` | зелёный | сервер, бэкенд |
| `db` | жёлтый | данные |
| `accent` | фиолетовый | API, инструменты |

:::mistake Запятая или двоеточие в тексте — только в кавычках
`{text: готовит, гостю не видна}` YAML прочитает как два поля. Правильно: `{text: "готовит, гостю не видна"}`. Сборка находит такие ошибки и останавливается.
:::

## Слайды

`slides.md` — слайды разделяются строкой `---`. Заметки для ментора пишутся в `script.md` (см. ниже) и видны по клавише S. `<!-- class: statement -->` в начале слайда делает крупный тезис на весь экран.

Правила:
- один слайд — одна мысль, ≤ 6 пунктов;
- никакого текста абзацами;
- схемы — через `:::use id`.

## Сценарий к слайдам

`script.md` — что рассказывать на занятии. Один раздел `##` на каждый слайд, считая титульный, в том же порядке, что в `slides.md`. Сборка и `lint:content` проверяют, что число разделов совпадает с числом слайдов.

Из этого файла собираются:
- страница «Сценарий к слайдам» — кнопка на странице урока: слева текст, справа текущий слайд. Если слайды открыты в соседней вкладке или окне, сценарий листается вместе с ними. У каждого слайда есть поле комментария, внизу — общий комментарий и кнопка «Скачать промпт на исправления»: файл с комментариями и ссылками на строки `slides.md`, `script.md` и связанный раздел `lesson.md`;
- заметки в самих слайдах — клавиша S;
- файл `.md` для скачивания.

```md
Что открыть заранее: … (текст до первого раздела — блок «Перед занятием»)

## Заголовок слайда (5 мин)

**На слайде:** что изображено, одной фразой.

**Рассказать:**
- тезис
- тезис

**Спросить:** вопрос ученику и ожидаемый ответ.

**Показать вживую:** что открыть и сделать.
```

### Витринное оформление

Во фронтматтере урока — `slides: theme: showcase`: крупная типографика, шаги с номерами в кружках, цветная шапка таблиц, номер урока на титульном слайде. Для урока 1 ещё `cover:` и `coverCredit:` — фото на титуле.

Макет слайда — комментарий в первой строке слайда: `<!-- class: имя -->`.

| Класс | Что получится |
|---|---|
| `part` | разделитель части на цветном фоне, «Часть N» подставляется сам |
| `statement` | крупный тезис; второй абзац — мелкое пояснение |
| `cards` | список `- **Заголовок** текст` → цветные карточки |
| `numbers` | список `- **7** подпись` → крупные числа |
| `photo` | текст слева, картинка справа на всю высоту (обрезается по размеру) |
| `photo contain` | то же, но скриншот вписывается целиком |
| `photos` | несколько фото в ряд через `:::cols` |

Картинки на слайдах увеличиваются по щелчку, Esc закрывает. Котики — только в уроке 1.

### Воркшоп

Перед «Домашним заданием» в каждом уроке — слайд `## Воркшоп: что собираем`. На нём 4–6 шагов. Ментор на своём примере показывает, как всё из урока складывается в одну работу: от пустой папки до результата.

Раздел сценария к нему — самый подробный:
- **Подготовить заранее:** что открыть и положить, чтобы не тратить время на занятии;
- **Показать вживую:** пронумерованные шаги, в каждом — какое меню, кнопка или сочетание клавиш и что должно получиться, в том числе нарочно сделанная ошибка и как её найти;
- **Рассказать:** как это связано с домашним заданием.

Длительность — 12–20 минут. `lint:content` проверяет, что слайд и раздел есть и в разделе не меньше четырёх шагов.

Правила:
- в каждом разделе есть «На слайде» и «Рассказать» или «Показать вживую»;
- только тезисы, без готового текста для зачитывания;
- сумма минут — около 90.

## Задания и материалы ментора

- **`homework/NN-slug/task-K/`** — заготовки и `tests.js`. До урока `tooling` задачи — и вёрстка, и JS — проверяются в браузере (`homework/_runner`), начиная с `tooling` — через Vitest (`npm test`).
- **`mentor/NN-slug/notes.md`** — вопросы для проверки понимания, типичные ошибки, критерии по каждому заданию, ответы на квиз.
- **`mentor/NN-slug/task-K/`** — эталон: только изменённые файлы, они кладутся поверх заготовки.

`npm run check:homework` проверяет, что тесты падают на заготовке и проходят на эталоне.

Раннер в `tests.js`:
- `test('название', () => { expect(x).toBe(1); })` — проверка; ещё `toEqual`, `toBeTruthy`, `toBeGreaterThan`, `toContain`, `toThrow`;
- `$`, `$$`, `css(el, 'свойство')` — помощники для вёрстки;
- `test.keep(…)` — ограничение, верное уже на заготовке («без !important», «на ноутбуке ничего не сломалось»). Иначе `check:homework` предупредит о пустой проверке;
- `screenWidth()` — ширина окна для адаптивных заданий. Названия и условия проверок строятся от неё, а плашка перепроверяет страницу при изменении ширины;
- `// widths: 375, 800, 1280` первой строкой — `check:homework` прогонит задание на каждой ширине.

## Страницы проектов

`src/projects/<id>.md` — ТЗ проекта. Картинки — в `src/projects/img/<id>/`, в тексте — `img/<id>/файл.webp`, описание скриншотов — в `src/projects/screenshots.yml`. Работают те же блоки, что в уроках. Если на странице есть `:::task`, внизу появляется отчёт для ментора — архив `project-<id>-report.zip`.

## Проверки перед сдачей урока

```bash
npm run build          # сборка без предупреждений
npm run lint:content   # объём, стоп-слова, примеры в каждом разделе
npm run check:links    # ссылки и якоря
npm run check:layout   # ничего не вылезает за границы на 4 ширинах, нет ошибок в консоли
npm run test:ui        # ответы, отчёт, комментарии к слайдам, Esc и синхронизация — в настоящем Chrome
```

Или всё сразу: `npm run check`.
